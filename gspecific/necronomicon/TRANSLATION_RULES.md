# Necronomicon 번역 규칙

Necronomicon PC-98의 `MES_lang.json` 번역 작업에 적용하는 규칙이다.

## 작업 범위

- 코드폴더: `C:\work_han\translation`
- 작업폴더: `C:\work_han\workspace1`
- 번역 JSON: `C:\work_han\workspace1\script-pc98\MES\*_lang.json`
- 현재 단계에서는 번역과 검증에 집중하며, 사용자가 별도로 요청하기 전에는 MES 인코딩을 진행하지 않는다.

## 문장 정렬

- 원문과 번역문은 반드시 동일한 `offset` 항목에 기록한다.
- 문장 순서, 항목 순서, `offset`은 변경하거나 재배열하지 않는다.
- 한 문장을 다른 항목으로 합치거나 나누지 않는다.
- 번역으로 인해 원문과 다른 문장을 번역하는 일이 없도록 `offset`을 기준으로 작업한다.
- 작업 전후에 모든 항목의 `offset`이 고유한지 확인한다.

## MES 줄 규칙

- 이 게임의 MES 텍스트는 한 줄에 32자,즉 64바이트 기준을 사용한다.
- 인코딩 시 줄 경계는 원본 규칙을 따른다.
- 번역문을 원문 문장과 혼동하지 않도록 임의로 줄을 합치거나 재배열하지 않는다.
- 문장 길이와 줄바꿈 처리는 인코더가 사용하는 MES 규칙을 따르며,번역 단계에서 offset을 움직이지 않는다.

## 한국어 표기

- 화자명은 다음 표기를 사용한다.
  - `トマス` → `「토머스」`
  - `ジョナサン` → `「조너선」`
  - `ガードナー` → `「가드너」`
  - `コーデリア` → `「코델리아」`
  - `ドロシー` → `「도로시」`
  - `マーシュ` → `「마시」`
  - `トマス` 외 음성 화자 → `「음성」`
- `インスマウス` → `인스머스`
- `アーカム` → `아캄`
- `ダニッジ` → `던위치`
- `ミスカトニック` → `미스카토닉`
- `クトゥルー` → `크툴루`
- `ダゴン` → `다곤`
- `ネクロノミコン` → `네크로노미콘`
- `魚鱗亭` → `어린정`
- 문맥상 이미 정해진 고유명사 표기를 우선하며,같은 인물·장소는 파일이 달라도 동일하게 표기한다.

## 구두점과 띄어쓰기

- 한국어 번역에서 마침표(`.`) 또는 쉼표(`,`) 뒤에는 공백을 넣지 않는다.
  - 올바름: `그렇지만,아직 끝나지 않았다.`
  - 잘못됨: `그렇지만, 아직 끝나지 않았다.`
- 대사 시작 기호 `「` 앞에는 공백을 넣지 않는다.
  - 올바름: `「토머스」어서 가자.`
  - 잘못됨: ` 「토머스」어서 가자.`
- 일본어 원문의 장식용 전각 공백이나 패딩은 번역문에 불필요하게 복사하지 않는다.
- 의미 전달에 필요한 문장부호와 말줄임표(`……`)는 유지한다.
- 대사체는 화자의 성격과 장면에 맞춰 자연스러운 한국어로 옮기되,원문의 의미를 임의로 추가하거나 삭제하지 않는다.

## 손상 원문과 GPC 예외

- 원문이 GPC 디코딩 오류나 의미 없는 손상 문자열이라 번역할 수 없는 경우에는 다음처럼 처리한다.
  - `translation`: `"@keep"`
  - `status`: `"passed"`
- 손상 문자열을 추측해 임의의 대사로 복원하지 않는다.
- `@keep` 항목은 미번역으로 세지 않지만,검증 결과에는 별도로 기록한다.

## 번역 상태

- 정상적으로 번역한 항목:
  - `status`: `"translated"`
- 손상 원문을 보존한 항목:
  - `status`: `"passed"`
  - `translation`: `"@keep"`
- 아직 작업하지 않은 항목:
  - 기존의 `translation`과 `status`를 유지한다.

## 배치 작업과 검증

- 기본 작업 단위는 최대 20개 항목이다.파일의 남은 항목이 20개보다 적으면 남은 항목을 모두 처리한다.
- 각 배치 후 다음을 확인한다.
  - 번역 완료 수 / 전체 항목 수
  - 미번역 수
  - `@keep` 및 `passed` 수
  - `offset` 중복 여부
  - 번역문 안의 `[.,] ` 패턴 여부
- 번역 작업 중에는 인코딩하지 않는다.
- 인코딩이 필요한 경우에는 번역 JSON 검증이 끝난 뒤 별도 작업으로 진행한다.

## 화면 출력 그룹과 화자 정렬

- `A5` 제어 코드 바로 뒤에 이어지는 텍스트 레코드는 같은 화면의 다음 출력 줄(`continuation`)로 묶는다.
- `A5`로 시작하지 않는 텍스트 레코드는 새 화면 출력 그룹으로 취급한다.다른 제어 코드가 사이에 있으면 대사를 임의로 연결하지 않는다.
- 화면 그룹 정보는 각 `*_lang.json`의 `display_groups`에 기록한다.
  - `speaker`: 첫 줄이 `「화자」` 형식이면 해당 화자,없으면 `null`
  - `display_role`: `speaker`, `continuation`, `text`
  - `display_line_index`: 그룹 내부 줄 순서
  - `display_leading_cells`: 원문 줄 앞의 공백 셀 수
  - `display_speaker_content_start_cells`: 화자 닫는 괄호 뒤 본문 시작 위치
- 화자가 없는 첫 줄은 주인공 독백이나 서술일 수 있으므로 화자를 추정해 추가하지 않는다.
- 후속 번역이나 인코딩 시 이 메타데이터를 이용해 화자 줄의 다음 줄을 같은 화면 그룹으로 처리하고,원문에 있던 공백 정렬을 보존한다.
- 번역 JSON의 `translation`에는 화면 폭 때문에 생긴 연속 공백을 넣지 않는다.인코딩 시 번역된 `「화자」`의 실제 길이를 다시 계산해 후속 줄의 공백을 자동으로 생성한다.
- 화면 그룹 분석 도구: `gspecific.necronomicon.adv98_mes.annotate_display_groups`

## 인코딩 시 자동 정렬

- 자동 화자 정렬은 `gspecific.necronomicon.adv98_mes.encode_mes`에만 적용한다.
- 화자 줄은 번역된 `「화자」` 뒤에 본문 구분용 ASCII 공백 하나를 정규화한다.
- 같은 화면 그룹의 `continuation` 줄은 번역된 화자와 구분 공백의 셀 수만큼 ASCII 공백을 앞에 추가한다.
- 32자 경계에서 다음 줄로 넘어갈 때 줄 시작의 일반 공백이나 전각 공백은 버리고,화자 정렬 공백만 남긴다.
- 화자가 없는 그룹에는 화자 정렬을 적용하지 않는다.
- `MAIN.MES`를 포함한 메뉴·비대사 영역은 이 화자 정렬 대상이 아니다.

## 32자 내부 줄바꿈

- Necronomicon의 텍스트 레코드는 한 레코드 안에서도 32자 화면 폭에 맞춰 공백 패딩으로 다음 줄을 표현할 수 있다.
- 번역문에는 이 패딩 공백을 저장하지 않고, 인코딩 시 현재 번역문 길이를 기준으로 다시 생성한다.
- 줄바꿈 직전의 남은 셀은 일반 공백으로 채우고, 다음 줄은 번역된 화자의 본문 시작 셀에 맞춘다.
- 줄바꿈 직후에 원래 남아 있던 일반 공백이나 전각 공백은 제거해 중복 들여쓰기를 방지한다.
- `A5`로 분리된 후속 레코드에도 동일한 화자 정렬 규칙을 적용한다.
- 이 처리는 원본 게임의 화면 출력 방식을 보존하기 위한 것이며,임의로 `A5` 제어 코드를 삽입하지 않는다.

## 인코딩 테스트

- 테스트 대상: `OPEN1.MES`, `OPEN2.MES`
- 실행 도구: `gspecific.necronomicon.adv98_mes.encode_mes_batch`
- 결과 위치:
  - `kor-pc98/MES`
  - `kor-pc98-dosbox-x/MES`
- 두 파일 모두 인코딩 성공했으며 두 출력 폴더의 파일 내용이 동일함을 확인했다.

## 관련 도구

- MES 디코딩: `gspecific.necronomicon.adv98_mes.decode_mes`
- 일괄 인코딩: `gspecific.necronomicon.adv98_mes.encode_mes_batch`
- 대화 사전 생성: `gspecific.necronomicon.adv98_mes.make_dialogue_dictionary`
- 대화 사전 적용: `gspecific.necronomicon.adv98_mes.apply_dialogue_dictionary`
