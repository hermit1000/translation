# Dead of the Brain ADV98 MES 번역 규칙

## 우선순위

1. 자연스러운 한국어 문장
2. 캐릭터별 말투와 호칭의 일관성
3. 메시지 창 안에서의 줄바꿈과 가독성
4. 원본 MES의 매크로·segment 구조 보존
5. 파일 크기 최적화

바이트 절약 때문에 문장이 부자연스러워지면 안 됩니다.

다만 같은 말투와 의미를 유지하면서 더 짧고 자연스러운 표현이 있다면
적극적으로 사용합니다.

```text
왜 내가 그런 잡일까지 해야 하는 거야. 덕분에 오늘도 또 야근이군.
→ 왜 내가 그런 잡일까지 해야 하지. 덕분에 오늘도 야근이군.
```

이처럼 불필요한 반복이나 장황한 어미를 줄여 화면 폭을 확보할 수 있습니다.

조사나 수식어가 겹쳐 장황해지는 경우에도 자연스러움을 해치지 않는 범위에서
간결하게 줄입니다.

```text
벽 칠하는 일은 일꾼에게 시키면 되는데
→ 벽 칠은 일꾼에게 시키면 되는데
```

## 캐릭터 말투

- 콜: 젊고 편한 반말, 다소 직설적이고 투덜거리는 말투
- 쿠거: 나이 든 연구자 말투. 콜에게는 편하게 말하지만 지나치게 가볍지 않게 표현
- 실라: 상황에 맞는 정중한 말투
- 화자명과 호칭은 `macro_catalog.json`의 표기를 기준으로 통일

## 매크로 표기

원본과 번역 모두 dictionary 매크로는 중괄호로 유지합니다.

```text
{コール：}원문{。}
{콜:}번역문{.}
```

- 화자·사전 단어: `{콜:}`, `{쿠거:}`
- 구두점 매크로: `{.}`, `{,}`, `{?}`, `{!}`, `{‥}`
- 원본에 있던 매크로는 삭제하지 않음
- `{.}`를 `{?}`로 바꾸는 것은 허용
- `{.}`를 중괄호 없는 `?`로 바꾸지 않음

구두점 매크로는 실제 문장 부호와 달리 MES 위치 정보를 보존하므로 반드시 중괄호를 유지합니다.

## Segment 경계

원본 대사가 여러 text segment로 나뉘어 있으면 그 경계를 보존합니다.

```text
{콜:}첫 번째 segment{.}두 번째 segment{?}
```

문장 세그먼트 경계는 `info.json`을 기준으로 빌더가 자동 처리합니다.

```text
첫 번째 segment와 두 번째 segment
```

별도의 세그먼트 구분 기호는 번역문에 넣지 않습니다.

## 줄바꿈과 문장 길이

- 메시지 창의 가로 폭과 줄 수를 넘지 않게 작성
- `.`, `,`, `?`, `!`가 새 줄 첫 칸에 홀로 오지 않게 조정
- 말줄임표가 어색하게 끊기지 않도록 문장을 줄이거나 늘림
- 필요하면 같은 의미를 유지하면서 더 짧거나 긴 표현으로 조정

원문과 동일한 바이트 길이를 맞출 필요는 없습니다. 다만 폰트 테이블에 없는 문자는 사용할 수 없습니다.

## 구두점과 공백

번역문은 사람이 읽기 쉽게 일반 문장 부호와 공백을 사용하되, 원본 매크로 위치는 `{}`로 보존합니다.

```text
{콜:}또야{?} 지난번에도...
```

구두점 뒤 공백 규칙:

- `.`와 `,` 뒤에는 공백을 넣지 않음
- `?`와 `!` 뒤에는 다음 문장이 이어질 때 공백을 넣음
- 말줄임표 `‥‥` 뒤에 새 문장이 이어지면 공백을 넣음
- 문장이 끝나고 줄이 바뀌는 경우에는 불필요한 공백을 넣지 않음

예:

```text
잘못된 형태: 왜 내가 그런 잡일까지 해야 하지. 덕분에 오늘도 야근이군.
권장 형태:   왜 내가 그런 잡일까지 해야 하지? 덕분에 오늘도 야근이군.
```

문맥상 질문이나 반문이면 마침표보다 물음표를 우선합니다.

예:

```text
없잖아‥‥ 그런데 아직 끝난 게 아니야.
```

단일 구두점 매크로는 직접 문자 코드로 저장하는 것이 더 작을 수 있지만, 번역자는 크기보다 가독성과 구조 보존을 우선합니다.

## 빌드 전 점검

- `original`과 `translation`의 매크로 개수가 일치하는지 확인
- `{}` 매크로를 임의로 삭제하지 않았는지 확인
- 캐릭터 말투와 호칭이 앞뒤 대사에서 일관적인지 확인
- 줄바꿈 결과에서 구두점이 고립되지 않는지 확인
- 문장 종료 매크로 `{.}`와 `{?}` 뒤에는 후행 공백을 넣지 않는다. 즉 `{.} `와 `{?} ` 형태는 사용하지 않는다.
- 다음 문장이 이어지는 경우에도 종료 매크로 뒤의 공백은 제거하고, 필요한 띄어쓰기는 다음 text 세그먼트의 시작 부분에서 조정한다.
