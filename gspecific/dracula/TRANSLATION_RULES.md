# Dracula 번역·인코딩 규칙

## 문자와 괄호

- 번역 JSON에서는 화자 괄호를 ASCII `[ ]`로 입력한다.
- 인코더와 한글 폰트 테이블이 `[ ]`를 게임의 2바이트 전각 괄호 코드
  `81 6D` / `81 6E`로 처리한다.
- Unicode `［］` 또는 `〔〕`를 번역문에 직접 입력하지 않는다. 현재 한글
  폰트 테이블에 해당 Unicode 문자가 직접 등록되어 있지 않다.
- `‥`(U+2025)는 폰트 코드 `8164`가 있으므로 원문처럼 유지한다.
- 일본어 마침표 `。`는 번역문에서 ASCII 마침표 `.`로 바꾼다.
- `…`는 사용하지 않고 `‥`로 입력한다.
- `‥.`처럼 생략부호 뒤에 ASCII 마침표를 붙인 경우, `.` 뒤에는 공백을
  넣지 않는다.
- MES 번역문에서는 일반 마침표 `.`와 쉼표 `,` 뒤에도 공백을 넣지 않는다.
  PC-98 폰트에서 문장부호가 한쪽으로 치우쳐 보이는 여백을 공백 대신
  활용한다.

## 줄 길이와 공백

- Dracula의 대사는 한 줄 40자 기준으로 작성한다.
- 공통 인코더의 `width` 인자는 실제 줄 길이보다 1 크게 지정하므로,
  Dracula 인코더는 `width=41`을 사용한다.
- 따라서 40자 뒤의 41번째 위치와 80자 뒤의 81번째 위치에 있는 줄바꿈용
  공백은 인코딩 시 제거한다. 이 공백은 화면의 다음 줄 시작 위치를 위한
  정렬용 공백과 구분해야 한다.
- 단, 41·42번째 또는 81·82번째가 연속 공백이면 정렬을 위한 공백으로
  간주하여 제거하지 않는다. Dracula 인코더는 이 예외를 적용한다.
- 이 게임의 표시 문자는 모두 2바이트 문자로 취급한다. 한글, 일본어,
  괄호, 공백 모두 한 글자로 센다.
- 화자 대사는 화자명과 뒤의 공백도 40자에 포함한다.
- 줄 길이와 다음 줄 들여쓰기를 계산할 때는 원문 화자명이 아니라 번역된
  `[화자명]`의 글자 수를 사용한다.
- 원문처럼 다음 줄로 이어지는 경우 개행 문자를 넣지 않고, 다음 줄의
  화자 영역에 해당하는 공백을 넣는다.
- 예를 들어 `[여인상] `은 6자이므로 첫 줄의 40자 계산에 6자를 포함하고,
  다음 줄은 공백 6자로 시작한다. `[드라큘라] `처럼 번역 화자명이 더
  길면 그 길이만큼 들여쓴다.
- JSON에는 전각 공백 `U+3000` 대신 일반 ASCII 공백을 사용한다. 인코더가
  폰트 테이블의 공백 코드에 맞게 처리한다.

## 번역 상태

- 영어만 있는 원문은 `@keep`을 사용한다.
- 번역이 완료된 항목의 `status`는 `translated`로 설정한다.
- 번역 JSON을 먼저 완성한 뒤 MES를 인코딩한다. 인코딩 결과는
  `kor-pc98/MES`와 `kor-pc98-dosbox-x/MES`에 함께 반영한다.
